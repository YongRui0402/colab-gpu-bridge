# 功能規格:讓 opencode 與 pi 輕鬆接上 Colab 上的 Ollama

**功能分支**:`feat/006-iteration`

**建立日期**:2026-11-16

**狀態**:草稿

**輸入**:使用者描述:「我下一步希望能夠讓這個服務可以輕鬆接到opencode和pi上」

## 使用者情境與測試 *(必填)*

### 使用者故事 1 - 用 opencode 接上 Colab 上的模型(優先順序:P1)

使用者開好工作階段、下載了模型後,在 UI 的「連線設定」畫面複製一段 opencode 的設定,貼進自己的 `opencode.json`,opencode 就能用 Colab 上的模型寫程式,包括讀檔、執行指令這類工具呼叫。

**為何是這個優先順序**:opencode 是使用者已經裝好、天天在用的 coding agent;這個故事做完,Colab 的 GPU 就能直接拿來寫程式。

**獨立測試**:另起臨時 `ollama serve` 當遠端,開工作階段並下載一個支援工具呼叫的模型 → 從連線設定畫面複製 opencode 片段寫進暫存 `HOME` 的設定 → 執行一次 `opencode run`,要它讀一個檔並回答檔案內容,確認它經本系統完成工具呼叫並答對。

**驗收情境**:

1. **假如**工作階段就緒、模型目錄有 `qwen2.5-coder:7b`,**當**使用者打開連線設定畫面,**則**看到一段 opencode 設定,provider 指向本系統的 `/v1`,模型清單就是目錄裡的模型。
2. **假如**使用者把片段原樣貼進 `opencode.json`,**當**在 opencode 選這個模型並要它讀一個檔,**則**opencode 呼叫讀檔工具、拿到內容並回答,過程沒有錯誤。
3. **假如**還沒下載任何模型,**當**使用者打開連線設定畫面,**則**看到「先到模型頁下載模型」的說明,不顯示空的模型清單。

**功能需求**:

- **FR-001**:連線設定畫面必須產生一段 opencode 設定片段:provider 使用 OpenAI 相容的介面、位址指向本系統相容端點的 `/v1`,並列出模型目錄裡每一個模型。
- **FR-002**:opencode 片段的每個模型必須帶上目前工作階段套用的 context 長度,讓 opencode 知道上限。
- **FR-003**:連線設定畫面必須提供一鍵複製片段;本系統不讀取、不寫入使用者自己的 opencode 設定檔。

**非功能需求**:

- 無

---

### 使用者故事 2 - 用 pi 接上 Colab 上的模型(優先順序:P2)

使用者在連線設定畫面切到 pi,複製一段 pi 的模型設定,放進 pi 的 `models.json`,pi 就能用 Colab 上的模型,包括工具呼叫。

**為何是這個優先順序**:pi 是使用者想用的第二個 coding agent;API 與故事 1 共用,只多一份片段格式。

**獨立測試**:同故事 1 的臨時 `ollama serve`;在暫存 `HOME` 安裝 pi,把複製的片段寫進它的 `models.json`,以非互動模式要它讀一個檔並回答,確認經本系統完成工具呼叫並答對。

**驗收情境**:

1. **假如**工作階段就緒、模型目錄有模型,**當**使用者在連線設定畫面切到 pi,**則**看到一段 pi 的 `models.json` 設定,位址指向本系統的 `/v1`,模型清單就是目錄裡的模型。
2. **假如**使用者把片段原樣放進 pi 的 `models.json`,**當**在 pi 選這個模型並要它讀一個檔,**則**pi 呼叫讀檔工具、拿到內容並回答,過程沒有錯誤。

**功能需求**:

- **FR-004**:連線設定畫面必須產生一段 pi 的模型設定片段:位址指向本系統相容端點的 `/v1`、使用 OpenAI Chat Completions 的介面,並列出模型目錄裡每一個模型。
- **FR-005**:pi 片段的每個模型必須帶上目前工作階段套用的 context 長度。

**非功能需求**:

- 無

---

### 使用者故事 3 - context 太小時提醒並給建議值(優先順序:P3)

使用者打開連線設定畫面時,如果目前套用的 context 比 coding agent 需要的小(例如 T4 自動套用的 4096),畫面會提醒,並給一個這台機器撐得住的建議值,告訴使用者怎麼改(開啟前覆蓋,或開著時套用並重啟)。

**為何是這個優先順序**:沒有它,opencode 與 pi 還是接得上,只是長一點的對話會被截掉;提醒能讓使用者知道原因並自己調。

**獨立測試**:以替身回報 T4 的設定(context 4096)開工作階段,打開連線設定畫面,確認出現提醒、建議值與改法;改用 context 32768 開,確認不出現提醒。

**驗收情境**:

1. **假如**工作階段就緒、目前 context 是 4096,**當**使用者打開連線設定畫面,**則**看到「context 太小,coding agent 的提示詞可能被截掉」的提醒、建議值,以及改設定的方法。
2. **假如**目前 context 不小於建議下限,**當**使用者打開連線設定畫面,**則**不出現提醒。
3. **假如**讀不到目前的設定(005 的 `unknown`),**當**使用者打開連線設定畫面,**則**片段照樣產生、不帶 context 長度,並說明讀不到目前的設定。

**功能需求**:

- **FR-006**:目前套用的 context 小於 coding agent 的建議下限(16384)時,連線設定畫面必須顯示提醒與建議值,並說明可用開啟前覆蓋或套用並重啟修改。
- **FR-007**:建議值必須依目前機器的顯示記憶體與平行數估算,不超過 005 的覆蓋範圍上限。
- **FR-008**:讀不到目前的設定時,片段不帶 context 長度,畫面說明原因。

**非功能需求**:

- 無

---

### 邊界情況

- 沒有就緒的工作階段時,`/v1/*` 回 OpenAI 格式的錯誤,說明沒有可用的工作階段,不排隊等待(同 001 規格對原生端點的做法)。
- `/v1` 底下沒開放的路徑(例如 `/v1/completions`、`/v1/embeddings` 以外的、管理類操作)回 OpenAI 格式的 404,說明只開放哪些路徑;Ollama 原生的管理操作照 001 規格維持回 403。
- 用戶端在串流途中斷線,本系統照 001 的做法立刻做健康檢查,不影響工作階段。
- 請求的模型不在目錄裡,照遠端 Ollama 的錯誤原樣傳回。
- 片段不含 token、Colab 的轉發位址或任何機密;只含本系統自己的位址。

## 全域需求 *(必填)*

### 功能需求

- **FR-009**(適用:使用者故事 1、2):相容端點必須開放 OpenAI 相容的 `POST /v1/chat/completions`(含串流與工具呼叫)與 `GET /v1/models`,轉送到目前就緒的工作階段並原樣傳回回應。
- **FR-010**(適用:使用者故事 1、2):沒有就緒的工作階段時,`/v1/*` 必須回 OpenAI 格式的錯誤(HTTP 503),不排隊等待。
- **FR-011**(適用:使用者故事 1、2):`/v1` 底下沒開放的路徑必須回 OpenAI 格式的 404,說明開放的路徑。
- **FR-012**(適用:使用者故事 1、2、3):連線設定畫面在沒有就緒的工作階段或模型目錄是空的時候,必須說明原因與下一步,不顯示不能用的片段。

### 非功能需求

- **NFR-001**(適用:使用者故事 1、2):經 `/v1/chat/completions` 串流時,本系統不得把回應整段收完才送出;每一段到了就轉送(門檻見 SC-003)。
- **NFR-002**(適用:使用者故事 1、2、3):連線設定畫面與片段的說明文字為繁體中文,片段本身的鍵名照各工具的原文。

## 關鍵實體

- **連線片段(ClientSnippet)**:給某一個 coding agent 貼上用的設定文字。屬性:工具(opencode 或 pi)、本系統的 `/v1` 位址、模型清單、每個模型的 context 長度。由模型目錄與目前工作階段的 Ollama 設定產生,不儲存。

## 成功標準 *(必填)*

### 可衡量成果

- **SC-001**:在本機臨時 `ollama serve` 當遠端的實跑中,opencode 以 UI 產生、未經手改的片段,完成一次需要讀檔工具的任務並答對。
- **SC-002**:同 SC-001 的環境,pi 以 UI 產生、未經手改的片段,完成一次需要讀檔工具的任務並答對。
- **SC-003**:替身每 0.1 秒送一段時,經 `/v1/chat/completions` 串流,用戶端收到每一段的時間比替身送出晚不超過 0.5 秒。
- **SC-004**:真的 Colab T4 上,opencode 以 UI 產生的片段完成 SC-001 的同一個任務(和 005 G-04 共用同一台,需要使用者本人同意並在場)。

## 假設

- 開放的 OpenAI 相容路徑只有 `/v1/chat/completions` 與 `/v1/models`;`/v1/completions`、`/v1/embeddings`、`/v1/responses` 這一輪不開(opencode 與 pi 接自架模型都走 Chat Completions)。
- 相容端點維持 001 的做法:只聽本機位址、沒有驗證;片段的 API key 欄位只填工具要求的佔位值。
- coding agent 的 context 建議下限定為 16384;實際值由 technical-research 依 opencode 與 pi 的提示詞長度修正。
- 支援工具呼叫與否取決於模型本身;本系統只原樣轉送,不替模型補工具呼叫。
- pi 在桌機沒有安裝;驗證時裝在暫存 `HOME`,不動使用者的環境。
