# 功能規格:模型目錄讀不到時回正確的錯誤,對話紀錄保留到工作階段結束

**功能分支**:`feat/007-iteration`

**建立日期**:2026-11-16

**狀態**:草稿

**輸入**:使用者描述:「修 Q30 模型目錄回 500(001 的 GET /api/models 讀不到遠端時回 500,合約寫 502/504;006 只在 /api/connect 接住)。對話測試可以保留到執行階段結束,不然換個分頁或重新整理紀錄就全部不見了。」

**時間預算**:3.4(使用者本人 2026-11-16 接受約 2~3.4 小時、兩個故事都做;原本 1 小時是 D1 分身代答,見釐清紀錄)

## 使用者情境與測試 *(必填)*

### 使用者故事 1 - 模型目錄讀不到時,看得到真正的原因(優先順序:P1)

使用者在工作階段就緒、但經通道連不到執行環境上的 Ollama、Ollama 回了看不懂的內容,或在時限內沒有回應時,打開模型頁或按「預先載入」,看到的是「連不到」「回應無法解讀」「沒有回應」這類說明,而不是一般的伺服器錯誤,也不會被誤導成「目錄是空的、還沒下載任何模型」。

**為何是這個優先順序**:這是 001 的合約已經寫好、程式沒做到的落差(006 `plan.md` Q30、`分身決策紀錄.md` D18 留下來的);回 500 時使用者分不出是本系統壞了還是 Colab 那一端的問題,也不知道該重試還是重開工作階段。改動集中在模型目錄,先做完就能消掉一個已知的錯誤回應。

**獨立測試**:工作階段就緒(替身)→ 讓替身的遠端 Ollama 分別「連不到」「回應格式不對」「逾時」→ 每種情況各呼叫一次列出模型目錄與預先載入 → 確認列出模型回 502、502、504 與 `OLLAMA_UNREACHABLE`、`OLLAMA_BAD_RESPONSE`、`OLLAMA_TIMEOUT`,預先載入也一樣,沒有任何一次是 500 → 打開模型頁,確認畫面顯示對應的繁體中文說明,不顯示空的目錄。

**驗收情境**:

1. **假如**工作階段就緒、經通道連不到執行環境上的 Ollama,**當**使用者打開模型頁,**則**UI API 回 502 與 `OLLAMA_UNREACHABLE`,模型頁顯示「連不到執行環境上的 Ollama」的說明,不顯示「還沒有下載任何模型」。
2. **假如**工作階段就緒、執行環境上的 Ollama 回了格式不對的內容,**當**使用者打開模型頁,**則**UI API 回 502 與 `OLLAMA_BAD_RESPONSE`,模型頁顯示「回應無法解讀」的說明。
3. **假如**工作階段就緒、執行環境上的 Ollama 在時限內沒有回應,**當**使用者打開模型頁,**則**UI API 回 504 與 `OLLAMA_TIMEOUT`,模型頁顯示「在時限內沒有回應」的說明。
4. **假如**目錄原本讀得到、使用者按下某個模型的「預先載入」時遠端卻連不到,**當**後端先確認目錄,**則**UI API 回 502 與 `OLLAMA_UNREACHABLE`,不受理這次預先載入,模型頁顯示對應說明,其他模型的狀態不變。
5. **假如**遠端恢復正常,**當**使用者重新打開模型頁或再按一次預先載入,**則**目錄照常顯示、預先載入照常受理,不需要重開工作階段。

**功能需求**:

- **FR-001**:列出模型目錄時讀不到執行環境上的 Ollama,系統必須照 001 `ui.openapi.yaml` 的 `listCatalog` 回應:連不到或回應格式不對回 502,逾時回 504,並帶 `OLLAMA_UNREACHABLE`、`OLLAMA_BAD_RESPONSE` 或 `OLLAMA_TIMEOUT` 與對應的繁體中文訊息(和 006 連線設定畫面 `GET /api/connect` 用同一套代碼)。
- **FR-002**:預先載入在確認目錄時讀不到執行環境上的 Ollama,系統必須照 001 `ui.openapi.yaml` 的 `preloadModel` 回 502 或 504 與上述代碼,不受理這次預先載入,也不改變任何模型的預先載入狀態。
- **FR-003**:模型頁收到列出模型目錄的 502 或 504 時,必須顯示錯誤代碼對應的說明,不得顯示成空的目錄或「還沒有下載任何模型」;收到預先載入的 502 或 504 時,必須顯示對應說明,目錄裡的其他模型照原狀顯示。

**非功能需求**:

- **NFR-001**:列出模型目錄與預先載入在讀不到執行環境上的 Ollama 時,UI API 不得回 500(門檻見 SC-001)。

### 使用者故事 2 - 對話紀錄保留到工作階段結束(優先順序:P2)

使用者在對話頁跟模型聊了幾輪,中途切到模型頁看一下、重新整理頁面,或在同一個瀏覽器另開一個分頁打開對話頁,回來時剛才的對話都還在,可以接著講;工作階段結束(使用者結束、閒置自動結束、被 Colab 收回、重連逾時,或變更執行階段類型換了新的工作階段)之後,對話就清掉,下一個工作階段從空白開始。

**為何是這個優先順序**:004 的對話頁一離開就不見,使用者試模型時常常要切到別頁看目錄或用量,回來就得重問一次;這個故事讓「試模型的基本能力」真的能連續試下去。排在故事 1 之後,是因為故事 1 修的是合約已經寫好的錯誤回應,這個故事是新的行為。

**獨立測試**:工作階段就緒(替身)、目錄有一個模型 → 在對話頁送出兩則訊息並收到回覆 → 重新整理頁面、切到模型頁再回來、另開新分頁打開對話頁,三次都確認兩問兩答照原順序、原內容顯示 → 再送出第三則,確認模型收到的是含前兩輪的完整對話 → 結束工作階段,確認開著的對話頁不用重新整理就清空並顯示說明 → 重新開一個工作階段,打開對話頁,確認對話是空的 → 查本系統的資料庫檔案與日誌,確認沒有任何一則對話內容。

**驗收情境**:

1. **假如**對話頁已經有兩問兩答,**當**使用者重新整理頁面,**則**兩問兩答照原順序、原內容顯示,選的模型不變。
2. **假如**對話頁已經有對話,**當**使用者切到模型頁再回到對話頁,**則**對話照原樣顯示。
3. **假如**對話頁已經有對話,**當**使用者在同一個瀏覽器另開一個分頁打開對話頁,**則**新分頁顯示同一段對話。
4. **假如**重新整理後對話還在,**當**使用者送出下一則訊息,**則**送給模型的是含先前每一輪的完整對話,模型能接著上下文回答。
5. **假如**模型正在回覆,**當**使用者重新整理或離開頁面,**則**回來時已收到的部分保留,這則回覆標示為中斷(和 004 使用者故事 2 驗收情境 8 的中斷標示一致),不顯示成正常完成。
6. **假如**對話頁開著且有對話,**當**工作階段以任何一種方式結束,**則**畫面不用重新整理就清空對話,並顯示「工作階段已結束,對話已清除」。
7. **假如**上一個工作階段留有對話、使用者當時沒有開著對話頁,**當**新的工作階段就緒後才打開對話頁,**則**對話是空的,不顯示上一個工作階段的內容。
8. **假如**對話頁有對話,**當**使用者換一個模型或按「清除」,**則**對話清空,重新整理後仍是空的(維持 004 換模型就清空的行為)。

**功能需求**:

- **FR-004**:系統必須在使用者的瀏覽器裡保存對話頁目前的對話(每則訊息、模型的回覆與中斷標示)與選的模型;同一個瀏覽器重新整理、切到別頁再回來或另開分頁打開對話頁時,必須照原順序還原。
- **FR-005**:還原後送出新訊息時,系統必須把還原的每一輪連同新訊息一起送給模型,和沒有離開頁面時一樣。
- **FR-006**:保存的對話必須屬於保存當時的工作階段;工作階段結束(使用者結束、閒置自動結束、被 Colab 收回、重連逾時、變更執行階段類型)後,系統必須清掉它:對話頁開著時不用重新整理就清空並顯示「工作階段已結束,對話已清除」,沒開著時下一次打開不顯示上一個工作階段的對話。
- **FR-007**:換模型或按「清除」時,系統必須同時清掉畫面上與保存的對話。
- **FR-008**:回覆途中重新整理或離開頁面時,系統必須保存已收到的部分並標示這則回覆中斷,還原時照中斷顯示。

**非功能需求**:

- **NFR-002**:對話內容只能存在使用者的瀏覽器裡,不得寫入本系統的資料庫與日誌;日誌照 001 的規則只記時間、模型、耗時與狀態碼。這一條修訂 004 NFR-002 的「離開或重新整理頁面即消失」(使用者原話,見假設),其餘不變(門檻見 SC-004)。

### 邊界情況

- 遠端只有其中一個查詢失敗(例如已下載清單讀得到、已載入清單逾時):整個目錄照失敗的那個代碼回 502 或 504,不回半套目錄。
- 讀不到顯示記憶體總量:維持 001 的行為,目錄照常回 200,`vramBytes` 與 `mayNotFit` 為 null,不算這一輪的錯誤。
- 沒有就緒的工作階段時列出模型或預先載入:維持 001 的 503 `NO_READY_SESSION`,不受這一輪影響。
- 兩個分頁同時開著對話頁、在其中一個送出訊息:另一個分頁重新整理或重新打開後顯示最新的對話;兩個分頁同時各自送出時,以最後保存的為準。
- 瀏覽器不允許保存(例如無痕模式的限制或空間不足):對話頁照 004 的行為照常可用,顯示「這個瀏覽器無法保存對話,離開或重新整理後會消失」。
- 工作階段在後端重新啟動後重連接回(同一個工作階段沒有結束):對話保留。
- 保存的對話選的模型已不在目錄裡(例如被刪除):對話照常顯示,送出前要使用者從目錄重新選一個模型(選了別的模型照 FR-007 清空)。

- 無

### 非功能需求

- **NFR-003**(適用:使用者故事 1、2):這一輪新增或改變的畫面說明與提示文字一律為繁體中文(沿用 001 的介面語言要求),錯誤代碼與模型名稱保留原文。

## 關鍵實體

- **保存的對話(SavedChat)**:對話頁目前的一段對話,存在使用者的瀏覽器裡。屬性:所屬的工作階段、選的模型、每則訊息(角色、內容、是否中斷與原因)、最後更新時間。屬於一個工作階段,工作階段結束即清除;不存在本系統的資料庫。

## 成功標準 *(必填)*

### 可衡量成果

- **SC-001**:以替身讓遠端 Ollama 分別連不到、回應格式不對、逾時,列出模型目錄與預先載入在三種情況下各自 100% 回 502、502、504 與對應的錯誤代碼,回 500 的次數為 0;模型頁顯示成空目錄的次數為 0。
- **SC-002**:對話頁有兩問兩答時,重新整理、切到別頁再回來、同一個瀏覽器另開分頁三種情況下,還原的訊息數、順序與內容 100% 與離開前一致;還原後送出的下一則請求 100% 含先前每一輪。
- **SC-003**:每一種結束方式(使用者結束、閒置自動結束、被 Colab 收回、重連逾時、變更執行階段類型)後 5 秒內,開著的對話頁不重新整理即清空;新工作階段打開對話頁時,顯示上一個工作階段的訊息數為 0。
- **SC-004**:跑完故事 2 的獨立測試後,本系統的資料庫檔案與日誌裡出現測試對話內容的次數為 0。

## 假設

- 使用者原話的「執行階段結束」指工作階段結束(004 原話的「執行階段的關閉」也是這個意思);變更執行階段類型會換一個新的工作階段,也算結束(分身代答,D3)。
- 使用者原話直接修訂了 004 NFR-002 的「離開或重新整理頁面即消失」與 004 假設的「不在範圍內:對話紀錄保存」;「不得寫入本系統的資料庫與日誌」維持不變(NFR-002)。
- 使用者本人 2026-11-16 決定(plan.md 待決問題 Q22)修訂 004 FR-008 的「回覆途中工作階段中斷…必須保留已收到的部分並標示中斷與原因」、004 使用者故事 2 驗收情境 8 與 004 邊界情況「對話頁選的模型在對話途中被下載佇列以外的方式移除(例如工作階段結束):照 FR-008 標示中斷」:回覆途中**工作階段結束**時,改照本 spec FR-006 先停止那一則、清空對話並顯示「工作階段已結束,對話已清除」,不再保留已收到的部分。004 FR-008 的其餘部分不變:沒有就緒的工作階段或沒有模型時不能送出;回覆途中模型服務回錯誤或逾時,仍保留已收到的部分並標示中斷與原因;回覆途中重新整理或離開頁面照本 spec FR-008 標示中斷。004 照舊行為寫的 e2e 跟著修訂(tasks T054b):回覆途中使用者結束改由 007 testplan US2-AJ-14 驗清空且重新整理後不復活;變更類型的清除由 US2-AJ-13 驗(沒有回覆在途中),回覆途中變更類型這個組合沒有專門案例,走和 US2-AJ-14 同一段清除。
- 保存只限同一個瀏覽器;換瀏覽器或換電腦看不到,不在範圍內(D3)。
- 每個模型各保留一段對話、跨工作階段保存對話、匯出對話,不在範圍內(D4)。
- 列出模型與預先載入以外呼叫模型目錄的地方(例如下載完成或預先載入結束後在背景推送目錄更新)讀不到遠端時的處理,不在這一輪範圍內,列進完成報告(D2)。
- 驗收用替身與本機測試;這一輪不需要任何 `colab` 指令或花 compute units 的實跑,也不對桌機 127.0.0.1:11434 送請求。
- 錯誤說明沿用現有的 `OLLAMA_UNREACHABLE`、`OLLAMA_BAD_RESPONSE`、`OLLAMA_TIMEOUT` 繁體中文訊息,不另訂新代碼。
