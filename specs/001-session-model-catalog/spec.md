# 功能規格:Colab GPU 工作階段管理與模型目錄

**功能分支**:`001-session-model-catalog`

**建立日期**:2026-11-09

**狀態**:草稿

**輸入**:使用者描述:「本地服務加一個 UI,把 Google Colab 的執行環境當成一台有 GPU 的虛擬機來用:在 Colab 上跑 Ollama 與開源模型,本地電腦透過通道呼叫它;從 UI 連到或自動開啟 Colab;模型快取在 Google Drive,縮短下載時間。第一個迭代:工作階段管理 + 模型目錄。」

## 使用者情境與測試 *(必填)*

### 使用者故事 1 - 一鍵開啟與結束 GPU 工作階段(優先順序:P1)

使用者打開本系統的 UI,選好執行階段類型(預設 T4 GPU)按一下「開啟」,系統就替他在 Colab 開好執行環境並把模型服務準備好;用完按「結束」,系統關掉執行環境、釋放資源;要換類型時,系統結束目前的再用新類型重開。執行環境被 Colab 收回、或本系統的後端重新啟動時,UI 顯示的狀態仍然是真的。

**為何是這個優先順序**:這是把 Colab 當成 GPU 機器來用的前提;沒有它,端點與模型目錄都沒有東西可接。只做完這一個故事,使用者就不必再手動開 notebook、執行啟動格。

**獨立測試**:在 UI 按「開啟」→ 等到狀態變成「就緒」→ 確認 Colab 帳號下確實有一個運作中的執行環境、模型服務有回應 → 按「結束」→ 確認狀態變成「已結束」,且 Colab 帳號下已沒有這個執行環境。

**驗收情境**:
1. **假如**目前沒有工作階段,**當**使用者按「開啟」,**則**狀態依序顯示「開啟中」→「就緒」,就緒時遠端模型服務已可回應。
2. **假如**工作階段「就緒」,**當**使用者按「結束」並確認,**則**狀態變成「已結束」(結束原因:使用者結束),且 Colab 帳號下不再有這個執行環境。
3. **假如**開啟過程失敗(例如沒有可用的 GPU、帳號授權失效),**當**系統放棄開啟,**則**狀態變成「開啟失敗」並顯示原因,且不留下任何已配置但沒人管的執行環境。
4. **假如**工作階段「就緒」,**當**執行環境被 Colab 收回,**則**系統偵測到並把狀態改為「失聯」(結束原因:被 Colab 收回),UI 提示可以重新開啟。
5. **假如**工作階段「就緒」且已載入模型,**當**本系統與 Colab 之間的連線短暫中斷後恢復,**則**狀態依序為「重連中」→「就緒」,接回的是同一個執行環境,已載入的模型仍在。
6. **假如**工作階段「重連中」,**當**超過重連時限仍接不回,**則**狀態變成「失聯」(結束原因:重連逾時),系統確保該執行環境被釋放,釋放不了就在 UI 明確警告。
7. **假如**工作階段「就緒」,**當**本系統的後端重新啟動,**則**後端啟動後重新接上同一個執行環境,狀態回到「就緒」,不會另開一個新的。
8. **假如**已有一個「開啟中」或「就緒」的工作階段,**當**使用者再按「開啟」,**則**系統不另開第二個執行環境,提示目前已有工作階段。
9. **假如**系統還沒有可用的 Colab 帳號授權(第一次使用或授權已過期),**當**使用者在 UI 按「登入 Colab」,**則**UI 顯示 Google 授權連結與授權碼輸入框;使用者在瀏覽器完成登入、把授權碼貼回 UI 後,UI 顯示已登入,之後不必再打開命令列設定。
10. **假如**使用者貼回的授權碼錯誤或已失效,**當**送出,**則**UI 顯示登入失敗與原因,可以重新取得授權連結。
11. **假如**目前沒有工作階段,**當**使用者選擇執行階段類型(例如 L4、高 RAM)再按「開啟」,**則**開出的執行環境就是所選的類型,UI 顯示目前的類型。
12. **假如**工作階段「就緒」且已載入模型 A,**當**使用者變更執行階段類型並確認「會結束目前的工作階段並重開」,**則**系統結束目前的執行環境、以新類型開啟,就緒後自動從網路重新下載並載入模型 A。
13. **假如**使用者變更執行階段類型,**當**新類型開不起來(例如沒有可用的該類 GPU),**則**狀態為「開啟失敗」並顯示原因,原本的執行環境已結束、不留遺留。
14. **假如**已經開過並結束過幾次工作階段,**當**使用者打開「紀錄」,**則**列出最近的工作階段,每筆有開啟與結束時間、執行階段類型、結束原因與運行時長。

**功能需求**:

- **FR-001**:系統必須讓使用者在 UI 一鍵開啟工作階段:在 Colab 依選定的執行階段類型(FR-009)配置執行環境,於其上啟動 Ollama 模型服務,並建立從本系統到該服務的連線。
- **FR-002**:系統必須讓使用者在 UI 結束工作階段,結束前必須有確認步驟;結束時必須釋放 Colab 上的執行環境。
- **FR-003**:系統必須追蹤並在 UI 顯示工作階段狀態:未開啟、開啟中、就緒、重連中、結束中、已結束、開啟失敗、失聯;已結束、開啟失敗與失聯必須附結束原因。
- **FR-004**:系統必須定期確認執行環境與模型服務是否仍存在。連線中斷時,系統必須把工作階段標為「重連中」並持續嘗試接回同一個執行環境,接回就回到「就緒」;確認執行環境已不存在,或超過重連時限仍接不回時,標為「失聯」並確保該執行環境被釋放。
- **FR-005**:後端重新啟動時,系統必須找回先前由它開啟、仍在運作的執行環境並重新接上,而不是視為不存在或另開新的。
- **FR-006**:同一時間最多只有一個工作階段;已有開啟中或就緒的工作階段時,系統必須拒絕再開新的並提示。
- **FR-007**:開啟失敗或結束時,系統必須確認 Colab 帳號下沒有遺留由它開啟的執行環境;發現遺留必須釋放,釋放不了必須在 UI 明確警告。
- **FR-008**:系統必須讓使用者在 UI 完成 Colab 帳號登入授權:顯示 Google 授權連結、接收使用者貼回的授權碼並保存授權;UI 必須顯示目前是否已登入。沒有有效授權時,「開啟」必須引導使用者先登入。
- **FR-009**:系統必須讓使用者在開啟前選擇執行階段類型(GPU 種類、是否高 RAM),預設 T4;UI 必須顯示目前工作階段的類型。
- **FR-010**:工作階段開著時變更執行階段類型,系統必須先提示「會結束目前的工作階段並重開」,確認後結束目前的執行環境、以新類型開啟,並在就緒後從網路重新下載並載入原本已載入的模型。

**非功能需求**:

- **NFR-001**:從按下「開啟」到「就緒」(不含模型載入)的時間門檻見 SC-001;開啟中必須顯示目前進行到哪一步。
- **NFR-002**:執行環境被收回後,UI 反映為「失聯」的時間門檻見 SC-002。

### 使用者故事 2 - 透過固定的 Ollama 相容端點使用遠端模型(優先順序:P1)

使用者在家中區網任一台電腦上的其他程式(例如對話工具、腳本)裡,把本系統的 Ollama 相容端點(原稱「本地端點」)設定一次,當作一般的 Ollama 服務使用;實際的推論跑在目前的 Colab 工作階段上。換了一個新的執行環境,這些程式的設定都不用改。

**為何是這個優先順序**:這是本產品的核心——把 Colab 當成區網內的遠端 Ollama 來用;排在故事 1 之後,只因為它建立在故事 1 的工作階段之上。

**獨立測試**:工作階段就緒且遠端已有一個模型 → 從區網內另一台電腦用標準的 Ollama 用戶端對 Ollama 相容端點送出產生文字的請求 → 收到回應,且確認推論是在 Colab 上執行(例如遠端服務的模型清單與本機不同) → 結束工作階段後再送一次,收到明確的「目前沒有可用的工作階段」錯誤。

**驗收情境**:
1. **假如**工作階段「就緒」,**當**區網內的程式對 Ollama 相容端點送出推論或查詢請求(列模型、產生文字、對話、embeddings、查模型資訊),**則**請求被轉送到目前的工作階段,回應原樣傳回,串流回應也逐段傳回。
2. **假如**沒有「就緒」的工作階段,**當**程式對 Ollama 相容端點送出請求,**則**在 1 秒內收到明確的錯誤,說明目前沒有可用的工作階段,而不是長時間等待後逾時。
3. **假如**工作階段結束後又開了一個新的,**當**程式用同一個 Ollama 相容端點送出請求,**則**請求送到新的工作階段,程式端不需要改任何設定。
4. **假如**工作階段「就緒」,**當**任何裝置繞過本系統、嘗試直接連到 Colab 上的遠端模型服務,**則**連不到;不存在任何能從網際網路直接存取該服務的公開網址。
5. **假如**工作階段「就緒」,**當**區網內的程式透過 Ollama 相容端點要求下載、刪除或建立模型,**則**收到明確的錯誤,說明這類操作請到 UI 進行,執行環境上的模型都不受影響。

**功能需求**:

- **FR-011**:系統必須提供一個固定位址的 Ollama 相容端點,開放推論與查詢操作(列模型、產生文字、對話、embeddings、查模型資訊),把請求轉送到目前就緒的工作階段並傳回回應,包含串流回應。
- **FR-012**:Ollama 相容端點收到管理模型的操作(下載、刪除、建立、複製、推送模型)時,必須回傳明確的錯誤,說明請到 UI 操作,且不執行該操作。
- **FR-013**:沒有就緒的工作階段時(含重連中),Ollama 相容端點收到推論或查詢請求,必須回傳明確的「沒有可用的工作階段」錯誤,不排隊等待(門檻見 SC-007);管理模型的操作一律依 FR-012 回錯誤。

**非功能需求**:

- **NFR-003**:遠端模型服務不得透過任何公開網址暴露;只有本系統經由受 Colab 帳號驗證的連線能存取它。
- **NFR-004**:經 Ollama 相容端點轉送所增加的延遲門檻見 SC-005。

### 使用者故事 3 - 挑選要下載的模型並使用執行環境上的模型目錄(優先順序:P2)

使用者每次新開的執行環境都是空的,所以要在 UI 瀏覽精選清單、搜尋 Ollama 官方模型庫,勾選一個或多個模型排進下載佇列(也可以直接輸入名稱),系統在背景把模型從網路下載到目前的執行環境,不影響正在使用的模型。UI 的模型目錄列出這台執行環境上已下載的模型;區網的程式指名其中任何一個,系統就載入後回應,也可以在 UI 預先載入,讓第一個請求不用等。執行環境結束後,上面的模型跟著消失。

**為何是這個優先順序**:每次新的執行環境都是空的,這個故事決定開啟後多快能真的用上模型;但沒有故事 1 的工作階段就沒有地方可以下載。

**獨立測試**:開啟工作階段(執行環境上沒有模型)→ 在 UI 搜尋並勾選一個小模型與一個約 4.7GB 的模型加入下載 → 確認依序下載、各自顯示進度,完成後出現在模型目錄 → 從區網用 Ollama 相容端點指名其中一個即可推論 → 下載期間推論延遲符合 SC-008 → 指名一個沒下載的模型,收到「模型不存在」。

**驗收情境**:
1. **假如**工作階段「就緒」且執行環境上已下載模型,**當**使用者打開模型目錄,**則**列出每個模型的名稱與大小,並標出哪些已載入。
2. **假如**目錄中有模型 A 且尚未載入,**當**使用者在 UI 按 A 的「預先載入」,**則**系統載入 A,目錄標示 A 已載入,之後指名 A 的第一個請求不必等載入。
3. **假如**執行環境上有模型 B 但尚未載入,**當**區網的程式透過 Ollama 相容端點指名 B 送出請求,**則**系統載入 B 後回應,不從網路下載。
4. **假如**執行環境上沒有模型 C,**當**區網的程式指名 C 送出請求,**則**收到「模型不存在」的錯誤,系統不自動下載 C。
5. **假如**工作階段「就緒」,**當**區網的程式透過 Ollama 相容端點列出模型,**則**回傳執行環境上已下載完成的模型,不含下載中的。
6. **假如**執行環境上沒有模型 B,**當**使用者輸入 B 的名稱下載,**則**UI 顯示下載進度;完成後 B 出現在目錄中。
7. **假如**模型 B 正在下載,**當**工作階段結束或失聯,**則**下載中斷,B 不會以「可用」狀態出現在任何目錄中。
8. **假如**使用者輸入的名稱不存在於模型來源,**當**送出下載,**則**顯示「找不到這個模型」,執行環境上的模型不變。
9. **假如**使用者打開「下載模型」,**當**瀏覽精選清單或以關鍵字搜尋 Ollama 官方模型庫,**則**列出符合的模型與各版本(例如 7b、4b-q4)的大小,執行環境上已有的標示「已下載」。
10. **假如**使用者勾選了三個尚未下載的模型,**當**按「加入下載」,**則**UI 先顯示總大小、執行環境剩餘磁碟空間與預估下載時間,確認後三個依序下載,每個顯示「排隊中」「下載中(進度)」「完成」或「失敗(原因)」。
11. **假如**下載佇列中有排隊中的模型,**當**使用者取消它,**則**它從佇列移除;正在下載的不受影響。
12. **假如**勾選的模型總大小超過執行環境剩餘磁碟空間,**當**按「加入下載」,**則**系統阻止加入並提示空間不足。
13. **假如**背景正在下載模型,**當**區網內的程式對 Ollama 相容端點送出推論請求,**則**請求照常回應,延遲符合 SC-008。



**功能需求**:

- **FR-014**:系統必須在 UI 列出目前執行環境上已下載的模型(名稱、大小、是否已載入)。
- **FR-015**:系統必須讓使用者在目錄預先載入一個模型。
- **FR-016**:Ollama 相容端點收到指名某個模型的請求時,若該模型已在執行環境上但尚未載入,系統必須載入後回應;若不在執行環境上,必須回傳「模型不存在」的錯誤,不得自動下載。Ollama 相容端點列出模型時,必須回傳執行環境上已下載完成的模型。
- **FR-017**:系統必須讓使用者輸入模型名稱,從網路下載該模型到目前的執行環境,過程中顯示進度;找不到該模型時回報錯誤且不改變已有的模型。
- **FR-018**:未完成的下載不得在目錄或 Ollama 相容端點的模型清單中顯示為可用。
- **FR-019**:(已移除)
- **FR-020**:系統必須在 UI 提供可下載的模型清單:一份使用者可編輯的精選清單列在最上方,並可用關鍵字搜尋 Ollama 官方模型庫;每個模型列出可選的版本與大小,執行環境上已有的標示為已下載。
- **FR-021**:系統必須讓使用者一次勾選多個模型加入下載佇列,依序下載並逐一顯示狀態(排隊中、下載中與進度、完成、失敗與原因);排隊中的項目可以取消。
- **FR-022**:加入下載前,系統必須顯示總大小、執行環境剩餘磁碟空間與預估下載時間;總大小超過剩餘空間時必須阻止加入。
- **FR-023**:(已移除)

**非功能需求**:

- **NFR-005**:開啟工作階段後下載一個常用大小的模型到可推論的時間門檻見 SC-004。
- **NFR-006**:模型大小超過目前執行階段類型的可用顯示記憶體(例如 T4 約 15GB)時,目錄必須標示可能無法載入,預先載入前也必須提示。
- **NFR-007**:下載在背景進行,不得影響正在進行的推論(門檻見 SC-008)。

### 使用者故事 4 - 掌握用量並避免忘了關(優先順序:P3)

使用者在 UI 隨時看得到 Colab compute units 的餘額、目前每小時的耗用與估計還能用多久;餘額快用完時收到警告,但系統不替他擋下。工作階段開著卻一段時間沒有人用,系統自動結束,避免白白扣點數。

**為何是這個優先順序**:保護點數、降低忘了關的成本;但不影響開啟、使用與選模型這些基本能力。

**獨立測試**:開啟工作階段 → 確認 UI 顯示的餘額與每小時耗用和 Colab 網頁上的一致 → 把閒置時限設為很短 → 不送任何請求 → 確認 UI 倒數、時間到自動結束(結束原因:閒置自動結束),Colab 帳號下沒有遺留執行環境。

**驗收情境**:
1. **假如**系統讀得到帳號用量,**當**使用者打開 UI,**則**顯示目前餘額、每小時耗用、估計可用時數與讀取時間。
2. **假如**餘額低於警告門檻,**當**使用者打開 UI 或按「開啟」,**則**顯示明顯警告,但仍允許開啟,進行中的工作階段也不被自動結束。
3. **假如**工作階段「就緒」且 Ollama 相容端點連續達到閒置時限都沒有請求,**當**時限到達,**則**系統自動結束工作階段(結束原因:閒置自動結束)。
4. **假如**工作階段閒置計時中,**當**Ollama 相容端點收到任何請求,**則**閒置計時歸零重算;UI 顯示距離自動結束的剩餘時間。
5. **假如**系統讀不到帳號用量,**當**使用者打開 UI,**則**餘額顯示為「未知」並說明原因,不影響開啟與結束。
6. **假如**閒置時限為 30 分鐘,**當**使用者在設定把它改成 10 分鐘並儲存,**則**閒置倒數立即改依 10 分鐘計算;餘額警告門檻的修改同樣立即反映在警告上。

**功能需求**:

- **FR-024**:系統必須自動取得 Colab 帳號的 compute units 餘額與每小時耗用,在 UI 顯示餘額、耗用、估計可用時數與讀取時間。
- **FR-025**:餘額低於警告門檻時,系統必須在 UI 顯示警告;不得因餘額而阻止開啟或自動結束工作階段。
- **FR-026**:工作階段「就緒」且 Ollama 相容端點連續達到閒置時限沒有請求時,系統必須自動結束工作階段;任何經 Ollama 相容端點的請求都重設閒置計時。
- **FR-027**:系統必須讓使用者設定閒置時限與餘額警告門檻。

**非功能需求**:

- **NFR-008**:用量資訊的更新頻率至少每 5 分鐘一次;顯示的資訊超過 15 分鐘未更新時必須標示為過期。

### 邊界情況

- 使用者連按兩次「開啟」:只會有一個工作階段(FR-006)。
- 變更執行階段類型的過程中(結束舊的、開新的之間),端點收到請求:回傳「沒有可用的工作階段」(FR-013),不排隊等待。
- 開啟到一半使用者按「結束」:系統停止開啟流程,釋放已配置的執行環境,狀態為「已結束」。
- Ollama 相容端點正在串流回應時連線中斷:這次串流中斷並回傳錯誤,工作階段進入「重連中」(FR-004);確認執行環境已被收回才標「失聯」。
- 餘額歸零:Colab 會回到免費方案限制,可能切斷本系統與執行環境的連線;系統依重連與失聯處理(FR-004),UI 額外提示餘額可能已歸零。
- Colab 帳號授權過期:開啟、結束或讀用量時失敗,UI 顯示「需要重新登入」並提供登入流程(FR-008),不當成工作階段失聯。
- 後端重啟時發現 Colab 上有運作中但不是由本系統開啟的執行環境:不接手、不關閉,只列出提示。
- 執行環境被收回或結束:上面已下載的模型跟著消失;重新開啟時目錄為空,佇列中未完成的項目保留,可再下載。
- 遠端磁碟或顯示記憶體不足以載入指名的模型:回報錯誤,已載入的其他模型不受影響。
- 兩個程式同時指名同一個尚未載入的模型:只載入一次,兩個請求都在載入完成後回應。

## 關鍵實體

- **工作階段(Session)**:一次在 Colab 上開啟到結束的執行環境使用期間。屬性:識別名稱、執行階段類型、狀態、結束原因、開啟時間、就緒時間、結束時間、最後一次請求時間。一個工作階段有零或多個已載入的模型。
- **模型(Model)**:目前執行環境上的一個模型。屬性:名稱(含版本,例如 qwen2.5:7b)、大小、狀態(可用、下載中)、下載完成時間、是否已載入。屬於一個工作階段,工作階段結束即不存在。
- **下載項目(DownloadJob)**:下載佇列中的一筆。屬性:模型名稱(含版本)、大小、狀態(排隊中、下載中、完成、失敗、已取消)、進度、失敗原因、加入時間。完成後對應到一個模型。
- **精選清單項目(CuratedModel)**:使用者可編輯的精選清單中的一筆。屬性:模型名稱(含版本)、說明、建議的執行階段類型。
- **用量快照(UsageSnapshot)**:某次讀到的帳號用量。屬性:餘額、每小時耗用、讀取時間。
- **設定(Settings)**:使用者可調整的值。屬性:閒置時限、餘額警告門檻。

## 假設

- 使用者只有一位(本人);一次只用一個 Colab 帳號(Colab Pro)。本系統跑在家中一台主機上,區網內其他電腦透過它使用模型。
- 可選的執行階段類型以 Colab CLI 支援的為準(GPU:T4、L4、G4、A100、H100;高 RAM);預設 T4。TPU 不在第一個迭代範圍內(Ollama 不使用 TPU)。各類型能否實際開到、每小時耗用多少,由 technical-research 實測。
- 第一個迭代以容器交付並在 Ubuntu 桌機上驗收;實際部署到 Unraid(Tower)留到下一個迭代。
- 模型服務使用 Ollama;Ollama 相容端點相容 Ollama 的 API,不另外提供 OpenAI 相容 API。
- 系統透過 Google 官方的 Colab 命令列工具開啟、操作與結束執行環境,以及讀取用量。此工具能否在 Colab Pro 帳號上做到這些事,由 technical-research 實測;若做不到,回到 specify 修訂故事 1 與故事 4。
- 遠端服務與本系統之間的連線不經過公開網址(NFR-003)。可行的連線方式由 technical-research 實測決定。
- Colab 帳號的登入授權由使用者在 UI 中完成(在瀏覽器登入 Google、把授權碼貼回 UI);之後系統沿用已保存的授權,直到過期。
- 第一個迭代不使用 Google Drive:實測在 GPU 執行環境上,網路下載比 Drive 冷讀快(見 research.md R4),且 Drive 每台新的執行環境都要手動授權;Drive 快取不在範圍內。
- 模型下載來源為 Ollama 官方模型庫。官方模型庫是否有可靠的搜尋與版本查詢方式,由 technical-research 查證;查不到時,FR-020 退為只有精選清單加輸入名稱。
- 下載在目前的 Colab 工作階段上背景執行,模型存在執行環境的本機磁碟(research.md R5);實測背景下載不影響推論延遲。
- 工作階段結束時,佇列中尚未完成的項目保留在佇列,下次可繼續;正在下載的依使用者故事 3 驗收情境 7 處理。
- 閒置時限預設 30 分鐘,餘額警告門檻預設 10 個 compute units,重連時限預設 5 分鐘。
- 日誌只記錄請求的時間、模型、耗時與狀態碼,不記錄 prompt 與回應的內容。
- SC-007 的「1 秒內」是澄清時採用的預設(使用者未逐題拍板),用來取代 FR-013 原本的「立即」;不合用可以推翻。
- 同時有多個請求時,依 Ollama 本身的處理方式排隊與並行,本系統不另外限制。
- 不做 UI 內的對話介面;使用模型一律透過 Ollama 相容端點。
- 不做 Colab notebook 網頁介面的自動化操作(瀏覽器自動化)。
- Colab 條款中「connecting to remote proxies」是否涵蓋本系統的連線方式仍模糊,列為風險,由 technical-research 查證。
