# 功能規格:Colab GPU 工作階段管理與模型目錄

**功能分支**:`001-session-model-catalog`

**建立日期**:2026-11-09

**狀態**:草稿

**輸入**:使用者描述:「本地服務加一個 UI,把 Google Colab 的執行環境當成一台有 GPU 的虛擬機來用:在 Colab 上跑 Ollama 與開源模型,本地電腦透過通道呼叫它;從 UI 連到或自動開啟 Colab;模型快取在 Google Drive,縮短下載時間。第一個迭代:工作階段管理 + 模型目錄。」

## 使用者情境與測試 *(必填)*

### 使用者故事 1 - 一鍵開啟與結束 GPU 工作階段(優先順序:P1)

使用者打開本系統的 UI,選好執行階段類型(預設 T4 GPU)按一下「開啟」,系統就替他在 Colab 開好執行環境並把模型服務準備好;用完按「結束」,系統關掉執行環境、釋放資源;要換類型時,系統結束目前的再用新類型重開。執行環境被 Colab 收回、或本系統的後端重新啟動時,UI 顯示的狀態仍然是真的。

**為何是這個優先順序**:這是把 Colab 當成 GPU 機器來用的前提;沒有它,端點與模型目錄都沒有東西可接。只做完這一個故事,使用者就不必再手動開 notebook、執行啟動格。

**獨立測試**:在 UI 按「開啟」→ 等到狀態變成「就緒」→ 確認 Colab 帳號下確實有一個運作中的執行環境、模型服務有回應 → 按「結束」→ 確認狀態變成「已結束」,且 Colab 帳號下已沒有這個執行環境。

**驗收情境**:

1. **假如**目前沒有工作階段,**當**使用者按「開啟」,**則**狀態依序顯示「開啟中」→「就緒」,就緒時遠端模型服務已可回應。
2. **假如**工作階段「就緒」,**當**使用者按「結束」並確認,**則**狀態變成「已結束」(結束原因:使用者結束),且 Colab 帳號下不再有這個執行環境。
3. **假如**開啟過程失敗(例如沒有可用的 GPU、帳號授權失效),**當**系統放棄開啟,**則**狀態變成「開啟失敗」並顯示原因,且不留下任何已配置但沒人管的執行環境。
4. **假如**工作階段「就緒」,**當**執行環境被 Colab 收回,**則**系統偵測到並把狀態改為「失聯」(結束原因:被 Colab 收回),UI 提示可以重新開啟。
5. **假如**工作階段「就緒」,**當**本系統的後端重新啟動,**則**後端啟動後重新接上同一個執行環境,狀態回到「就緒」,不會另開一個新的。
6. **假如**已有一個「開啟中」或「就緒」的工作階段,**當**使用者再按「開啟」,**則**系統不另開第二個執行環境,提示目前已有工作階段。
7. **假如**系統還沒有可用的 Colab 帳號授權(第一次使用或授權已過期),**當**使用者在 UI 按「登入 Colab」,**則**UI 顯示 Google 授權連結與授權碼輸入框;使用者在瀏覽器完成登入、把授權碼貼回 UI 後,UI 顯示已登入,之後不必再打開命令列設定。
8. **假如**使用者貼回的授權碼錯誤或已失效,**當**送出,**則**UI 顯示登入失敗與原因,可以重新取得授權連結。
9. **假如**目前沒有工作階段,**當**使用者選擇執行階段類型(例如 L4、高 RAM)再按「開啟」,**則**開出的執行環境就是所選的類型,UI 顯示目前的類型。
10. **假如**工作階段「就緒」且正在使用模型 A,**當**使用者變更執行階段類型並確認「會結束目前的工作階段並重開」,**則**系統結束目前的執行環境、以新類型開啟,就緒後自動載入模型 A。
11. **假如**使用者變更執行階段類型,**當**新類型開不起來(例如沒有可用的該類 GPU),**則**狀態為「開啟失敗」並顯示原因,原本的執行環境已結束、不留遺留。

**功能需求**:

- **FR-001**:系統必須讓使用者在 UI 一鍵開啟工作階段:在 Colab 依選定的執行階段類型(FR-021)配置執行環境,於其上啟動 Ollama 模型服務,並建立從本系統到該服務的連線。
- **FR-002**:系統必須讓使用者在 UI 結束工作階段,結束前必須有確認步驟;結束時必須釋放 Colab 上的執行環境。
- **FR-003**:系統必須追蹤並在 UI 顯示工作階段狀態:未開啟、開啟中、就緒、結束中、已結束、開啟失敗、失聯;已結束、開啟失敗與失聯必須附結束原因。
- **FR-004**:系統必須定期確認執行環境與模型服務是否仍存在;不存在時把工作階段標為「失聯」。
- **FR-005**:後端重新啟動時,系統必須找回先前由它開啟、仍在運作的執行環境並重新接上,而不是視為不存在或另開新的。
- **FR-006**:同一時間最多只有一個工作階段;已有開啟中或就緒的工作階段時,系統必須拒絕再開新的並提示。
- **FR-007**:開啟失敗或結束時,系統必須確認 Colab 帳號下沒有遺留由它開啟的執行環境;發現遺留必須釋放,釋放不了必須在 UI 明確警告。
- **FR-008**:系統必須讓使用者在 UI 完成 Colab 帳號登入授權:顯示 Google 授權連結、接收使用者貼回的授權碼並保存授權;UI 必須顯示目前是否已登入。沒有有效授權時,「開啟」必須引導使用者先登入。
- **FR-021**:系統必須讓使用者在開啟前選擇執行階段類型(GPU 種類、是否高 RAM),預設 T4;UI 必須顯示目前工作階段的類型。
- **FR-022**:工作階段開著時變更執行階段類型,系統必須先提示「會結束目前的工作階段並重開」,確認後結束目前的執行環境、以新類型開啟,並在就緒後載入原本使用中的模型。

**非功能需求**:

- **NFR-001**:從按下「開啟」到「就緒」(不含模型載入)的時間門檻見 SC-001;開啟中必須顯示目前進行到哪一步。
- **NFR-002**:執行環境被收回後,UI 反映為「失聯」的時間門檻見 SC-002。

### 使用者故事 2 - 透過固定的本地端點使用遠端模型(優先順序:P1)

使用者在家中區網任一台電腦上的其他程式(例如對話工具、腳本)裡設定一次本系統的固定網址,當作一般的 Ollama 服務使用;實際的推論跑在目前的 Colab 工作階段上。換了一個新的執行環境,這些程式的設定都不用改。

**為何是這個優先順序**:這是本產品的核心——把 Colab 當成區網內的遠端 Ollama 來用;排在故事 1 之後,只因為它建立在故事 1 的工作階段之上。

**獨立測試**:工作階段就緒且遠端已有一個模型 → 從區網內另一台電腦用標準的 Ollama 用戶端對本系統的端點送出產生文字的請求 → 收到回應,且確認推論是在 Colab 上執行(例如遠端服務的模型清單與本機不同) → 結束工作階段後再送一次,收到明確的「目前沒有可用的工作階段」錯誤。

**驗收情境**:

1. **假如**工作階段「就緒」,**當**區網內的程式對本系統的端點送出 Ollama 相容的請求(列模型、產生文字、對話),**則**請求被轉送到目前的工作階段,回應原樣傳回,串流回應也逐段傳回。
2. **假如**沒有「就緒」的工作階段,**當**程式對本地端點送出請求,**則**立即收到明確的錯誤,說明目前沒有可用的工作階段,而不是長時間等待後逾時。
3. **假如**工作階段結束後又開了一個新的,**當**程式用同一個本地網址送出請求,**則**請求送到新的工作階段,程式端不需要改任何設定。
4. **假如**工作階段「就緒」,**當**任何裝置繞過本系統、嘗試直接連到 Colab 上的遠端模型服務,**則**連不到;不存在任何能從網際網路直接存取該服務的公開網址。

**功能需求**:

- **FR-009**:系統必須提供一個固定位址的 Ollama 相容端點,把請求轉送到目前就緒的工作階段並傳回回應,包含串流回應。
- **FR-010**:沒有就緒的工作階段時,本地端點必須立即回傳明確的「沒有可用的工作階段」錯誤。

**非功能需求**:

- **NFR-003**:遠端模型服務不得透過任何公開網址暴露;只有本系統經由受 Colab 帳號驗證的連線能存取它。
- **NFR-004**:經本地端點轉送所增加的延遲門檻見 SC-005。

### 使用者故事 3 - 挑選要下載的模型並從 Google Drive 的模型目錄選用(優先順序:P2)

使用者把常用的模型存在自己的 Google Drive,每次開新的執行環境時不必重新從網路下載。UI 列出 Drive 上已有的模型,選一個就從 Drive 載入成為目前使用的模型;Drive 上還沒有的模型,可以在 UI 瀏覽精選清單、搜尋 Ollama 官方模型庫,勾選一個或多個排進下載佇列(也可以直接輸入名稱),下載一次存進 Drive,下次直接用;下載在背景進行,不影響正在使用的模型。

**為何是這個優先順序**:每次新的執行環境都是空的,這個故事決定開啟後多快能真的用上模型;但沒有故事 1 的工作階段就無從載入。

**獨立測試**:Drive 模型資料夾為空 → 開啟工作階段 → 輸入一個小模型名稱下載 → 確認下載進度、完成後模型出現在目錄並存在 Drive → 結束工作階段、重新開啟 → 目錄仍列出該模型,選用後不再從網路下載即可推論,且載入時間短於第一次的網路下載。

**驗收情境**:

1. **假如**工作階段「就緒」且 Drive 模型資料夾中有模型,**當**使用者打開模型目錄,**則**列出 Drive 上每個模型的名稱與大小,並標出哪一個是目前使用中。
2. **假如**目錄中有模型 A,**當**使用者選用 A,**則**系統從 Drive 載入 A 並設為目前使用的模型,本地端點的請求未指定模型時使用 A。
3. **假如**Drive 上沒有模型 B,**當**使用者輸入 B 的名稱下載,**則**UI 顯示下載進度;完成後 B 存在 Drive 上並出現在目錄中。
4. **假如**模型 B 正在下載,**當**工作階段結束或失聯,**則**下載中斷,B 不會以「可用」狀態出現在目錄中,Drive 上也不會留下會被誤認為完整的檔案。
5. **假如**使用者輸入的名稱不存在於模型來源,**當**送出下載,**則**顯示「找不到這個模型」,Drive 不被修改。
6. **假如**開啟的執行環境需要使用者手動授權才能存取 Drive,**當**系統走到掛載 Drive 這一步,**則**UI 顯示授權連結與說明,授權完成後繼續開啟流程。
7. **假如**使用者打開「下載模型」,**當**瀏覽精選清單或以關鍵字搜尋 Ollama 官方模型庫,**則**列出符合的模型與各版本(例如 7b、4b-q4)的大小,已存在 Drive 的標示「已下載」。
8. **假如**使用者勾選了三個尚未下載的模型,**當**按「加入下載」,**則**UI 先顯示總大小、Drive 剩餘空間與預估會花的 compute units,確認後三個依序下載,每個顯示「排隊中」「下載中(進度)」「完成」或「失敗(原因)」。
9. **假如**下載佇列中有排隊中的模型,**當**使用者取消它,**則**它從佇列移除,Drive 不被修改;正在下載的不受影響。
10. **假如**勾選的模型總大小超過 Drive 剩餘空間,**當**按「加入下載」,**則**系統阻止加入並提示空間不足。
11. **假如**背景正在下載模型,**當**區網內的程式對本系統的端點送出推論請求,**則**請求照常回應,延遲符合 SC-007。

**功能需求**:

- **FR-011**:系統必須在工作階段中存取使用者 Google Drive 上一個固定的模型資料夾,並在 UI 列出其中可用的模型(名稱、大小、是否為目前使用中)。
- **FR-012**:系統必須讓使用者從目錄選用一個模型,從 Drive 載入並設為目前使用的模型。
- **FR-013**:系統必須讓使用者輸入模型名稱,從網路下載該模型並存進 Drive 模型資料夾,過程中顯示進度;找不到該模型時回報錯誤且不修改 Drive。
- **FR-014**:未完成的下載不得在目錄中顯示為可用,也不得在 Drive 上留下會被當成完整模型的檔案。
- **FR-015**:存取 Drive 需要使用者手動授權時,系統必須在 UI 引導授權並在完成後繼續。
- **FR-023**:系統必須在 UI 提供可下載的模型清單:一份使用者可編輯的精選清單列在最上方,並可用關鍵字搜尋 Ollama 官方模型庫;每個模型列出可選的版本與大小,已存在 Drive 的標示為已下載。
- **FR-024**:系統必須讓使用者一次勾選多個模型加入下載佇列,依序下載並逐一顯示狀態(排隊中、下載中與進度、完成、失敗與原因);排隊中的項目可以取消。
- **FR-025**:加入下載前,系統必須顯示總大小、Drive 剩餘空間與預估會消耗的 compute units;總大小超過剩餘空間時必須阻止加入。

**非功能需求**:

- **NFR-005**:同一個模型從 Drive 載入的時間,必須短於從網路下載的時間(門檻見 SC-004)。
- **NFR-006**:模型大小超過目前執行階段類型的可用顯示記憶體(例如 T4 約 15GB)時,目錄必須在選用前提示可能無法載入。
- **NFR-012**:下載在背景進行,不得影響正在進行的推論(門檻見 SC-007)。

### 使用者故事 4 - 掌握用量並避免忘了關(優先順序:P3)

使用者在 UI 隨時看得到 Colab compute units 的餘額、目前每小時的耗用與估計還能用多久;餘額快用完時收到警告,但系統不替他擋下。工作階段開著卻一段時間沒有人用,系統自動結束,避免白白扣點數。

**為何是這個優先順序**:保護點數、降低忘了關的成本;但不影響開啟、使用與選模型這些基本能力。

**獨立測試**:開啟工作階段 → 確認 UI 顯示的餘額與每小時耗用和 Colab 網頁上的一致 → 把閒置時限設為很短 → 不送任何請求 → 確認 UI 倒數、時間到自動結束(結束原因:閒置自動結束),Colab 帳號下沒有遺留執行環境。

**驗收情境**:

1. **假如**系統讀得到帳號用量,**當**使用者打開 UI,**則**顯示目前餘額、每小時耗用、估計可用時數與讀取時間。
2. **假如**餘額低於警告門檻,**當**使用者打開 UI 或按「開啟」,**則**顯示明顯警告,但仍允許開啟,進行中的工作階段也不被自動結束。
3. **假如**工作階段「就緒」且本地端點連續達到閒置時限都沒有請求,**當**時限到達,**則**系統自動結束工作階段(結束原因:閒置自動結束)。
4. **假如**工作階段閒置計時中,**當**本地端點收到任何請求,**則**閒置計時歸零重算;UI 顯示距離自動結束的剩餘時間。
5. **假如**系統讀不到帳號用量,**當**使用者打開 UI,**則**餘額顯示為「未知」並說明原因,不影響開啟與結束。

**功能需求**:

- **FR-016**:系統必須自動取得 Colab 帳號的 compute units 餘額與每小時耗用,在 UI 顯示餘額、耗用、估計可用時數與讀取時間。
- **FR-017**:餘額低於警告門檻時,系統必須在 UI 顯示警告;不得因餘額而阻止開啟或自動結束工作階段。
- **FR-018**:工作階段「就緒」且本地端點連續達到閒置時限沒有請求時,系統必須自動結束工作階段;任何經本地端點的請求都重設閒置計時。
- **FR-019**:系統必須讓使用者設定閒置時限與餘額警告門檻。

**非功能需求**:

- **NFR-007**:用量資訊的更新頻率至少每 5 分鐘一次;顯示的資訊超過 15 分鐘未更新時必須標示為過期。

### 邊界情況

- 使用者連按兩次「開啟」:只會有一個工作階段(FR-006)。
- 變更執行階段類型的過程中(結束舊的、開新的之間),端點收到請求:回傳「沒有可用的工作階段」(FR-010),不排隊等待。
- 開啟到一半使用者按「結束」:系統停止開啟流程,釋放已配置的執行環境,狀態為「已結束」。
- 本地端點正在串流回應時工作階段被收回:串流中斷並回傳錯誤,工作階段標為「失聯」。
- 餘額歸零:Colab 會回到免費方案限制,可能切斷本系統與執行環境的連線;系統依失聯處理,UI 額外提示餘額可能已歸零。
- Colab 帳號授權過期:開啟、結束或讀用量時失敗,UI 顯示「需要重新登入」並提供登入流程(FR-008),不當成工作階段失聯。
- 後端重啟時發現 Colab 上有運作中但不是由本系統開啟的執行環境:不接手、不關閉,只列出提示。
- Drive 模型資料夾不存在:第一次使用時建立。
- 遠端磁碟空間不足以從 Drive 載入或下載模型:回報錯誤,不改變目前使用的模型。

## 全域需求 *(必填)*

### 功能需求

- **FR-020**(適用:使用者故事 1、4):工作階段每次狀態變化與結束,都必須保留紀錄(時間、狀態、結束原因、運行時長),UI 可查看最近的紀錄。

### 非功能需求

- **NFR-008**(適用:使用者故事 1、2、3、4):UI 與 Ollama 相容端點開放給家中區網(含 VPN 連回)存取,不需要登入;不得對外網公開。
- **NFR-009**(適用:使用者故事 1、2、3、4):Colab 帳號憑證、連線所需的金鑰與任何遠端位址只存在執行本系統的主機上權限受限的設定檔或資料夾中,不出現在 UI、日誌與版本控制裡。
- **NFR-010**(適用:使用者故事 1、2、3、4):介面語言為繁體中文。
- **NFR-011**(適用:使用者故事 1、2、3、4):本系統以容器交付,只靠一份 compose 設定與一份環境變數檔就能在一般 Linux 主機或 Unraid 上啟動;Colab 授權、工作階段紀錄與設定存在掛載的資料夾,容器重建後仍保留。

## 關鍵實體

- **工作階段(Session)**:一次在 Colab 上開啟到結束的執行環境使用期間。屬性:識別名稱、狀態、結束原因、開啟時間、就緒時間、結束時間、最後一次請求時間、目前使用的模型。一個工作階段有零或一個目前使用的模型。
- **模型(Model)**:存在 Drive 模型資料夾中的一個模型。屬性:名稱、大小、狀態(可用、下載中)、存入時間。
- **用量快照(UsageSnapshot)**:某次讀到的帳號用量。屬性:餘額、每小時耗用、讀取時間。
- **設定(Settings)**:使用者可調整的值。屬性:閒置時限、餘額警告門檻。

## 成功標準 *(必填)*

### 可衡量成果

- **SC-001**:從按下「開啟」到「就緒」(不含模型載入)在 5 分鐘內完成。
- **SC-002**:執行環境被收回或連線中斷後,UI 在 2 分鐘內顯示「失聯」。
- **SC-003**:每一次結束(使用者結束、閒置自動結束、開啟失敗)後 1 分鐘內,Colab 帳號下沒有遺留由本系統開啟的執行環境。
- **SC-004**:同一個模型(至少 4GB),從 Drive 載入到可推論的時間短於從網路下載到可推論的時間。
- **SC-005**:經本地端點轉送,和本系統所在主機直接連到遠端模型服務相比,單次非串流請求增加的延遲不超過 0.5 秒。
- **SC-006**:閒置時限到達後 1 分鐘內工作階段被自動結束。
- **SC-007**:背景下載模型期間,經本系統端點的單次非串流請求,延遲比沒有下載時增加不超過 0.5 秒。

## 假設

- 使用者只有一位(本人);一次只用一個 Colab 帳號(Colab Pro)。本系統跑在家中一台主機上,區網內其他電腦透過它使用模型。
- 可選的執行階段類型以 Colab CLI 支援的為準(GPU:T4、L4、G4、A100、H100;高 RAM);預設 T4。TPU 不在第一個迭代範圍內(Ollama 不使用 TPU)。各類型能否實際開到、每小時耗用多少,由 technical-research 實測。
- 第一個迭代以容器交付並在 Ubuntu 桌機上驗收;實際部署到 Unraid(Tower)留到下一個迭代。
- 模型服務使用 Ollama;本地端點相容 Ollama 的 API,不另外提供 OpenAI 相容 API。
- 系統透過 Google 官方的 Colab 命令列工具開啟、操作與結束執行環境,以及讀取用量。此工具能否在 Colab Pro 帳號上做到這些事,由 technical-research 實測;若做不到,回到 specify 修訂故事 1 與故事 4。
- 遠端服務與本系統之間的連線不經過公開網址(NFR-003)。可行的連線方式由 technical-research 實測決定。
- Colab 帳號的登入授權由使用者在 UI 中完成(在瀏覽器登入 Google、把授權碼貼回 UI);之後系統沿用已保存的授權,直到過期。
- Drive 模型資料夾位置固定(可在設定檔指定),第一個迭代不做多個資料夾。
- 模型下載來源為 Ollama 官方模型庫。官方模型庫是否有可靠的搜尋與版本查詢方式,由 technical-research 查證;查不到時,FR-023 退為只有精選清單加輸入名稱。
- 下載實際在哪裡執行(Colab 工作階段背景、另開一台不含 GPU 的執行環境、或本系統所在主機下載後上傳 Drive),規格不指定,由 technical-research 實測各候選的速度與花費後決定;不論在哪裡執行,都要符合 FR-024、FR-025 與 NFR-012。
- 工作階段結束時,佇列中尚未完成的項目保留在佇列,下次可繼續;正在下載的依驗收情境 4 處理(若下載位置不依賴工作階段,則不中斷)。
- 閒置時限預設 30 分鐘,餘額警告門檻預設 10 個 compute units。
- 不做 UI 內的對話介面;使用模型一律透過本地端點。
- 不做 Colab notebook 網頁介面的自動化操作(瀏覽器自動化)。
- Colab 條款中「connecting to remote proxies」是否涵蓋本系統的連線方式仍模糊,列為風險,由 technical-research 查證。
